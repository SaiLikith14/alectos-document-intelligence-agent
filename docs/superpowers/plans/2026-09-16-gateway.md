# Authentication gateway implementation plan

Goal: protect existing RAG endpoints using a separate public gateway with verified identity, owned-resource mappings, and a configurable one-run trial.

Architecture: browser -> gateway.main:app -> app.main:app. A shared server secret closes direct backend access. Gateway stores ownership and trial reservations in new PostgreSQL tables; existing RAG tables remain untouched. OIDC RS256 issuer/audience/JWKS are configured by the operator. Firebase setup is documented. Trial enforcement defaults off, never authentication.

1. Add tests for direct-access rejection, valid/invalid JWTs, ownership without session IDs, quota outcomes, and streaming completion/error handling.
2. Add gateway settings, token verifier, PostgreSQL store, migration, explicit proxy endpoints, and bounded SSE parsing. Reserve quota before processing; mark successful only on done. Fail closed on ambiguous interruptions and crashes; manual reconciliation prevents double consumption.
3. Add the backend shared-secret middleware and register it in app/main.py.
4. Verify tests, document deployment and frontend headers, package only changed/new files. Never include uploaded credentials, virtualenv, or repository history.

Release scope: gateway access controls only. Existing RAG quality and ingestion performance issues are outside this patch. Live identity-provider, PostgreSQL, and Gemini validation remain deployment gates when unavailable locally.
